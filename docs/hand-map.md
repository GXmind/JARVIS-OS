# 摄像头手势与独立地图窗口

本功能在 `feature/map-operation-hand` 开发。主窗口负责语音、摄像头和最初的路线规划；传送后，副屏拥有独立的路线副本、地图控制器、视野和退出操作，可用鼠标、触摸或明确指向副屏的摄像头手势操作。保持普通窗口，不使用全屏。

## 操作

1. 启动 JARVIS，先用原有文字或语音完成一条路线规划。
2. 按 **F9** 或点击底部“启用手势”。首次使用时，在 Edge 提示中允许本机页面访问摄像头。摄像头默认关闭，不随启动自动开启。
3. 让整只手进入画面，保持光照和背景稳定。预览显示实际识别到的关键点；“隐藏预览”只隐藏画面，F9 才关闭摄像头。
4. 地图加载后，可以用以下操作。

| 手势 | 操作 |
| --- | --- |
| 单手拇指与食指捏合，保持后移动 | 拖动地图；松开后加载新的地理视野 |
| 只伸出食指，保持后移动 | 左右旋转与上下俯仰 |
| 双手分别捏合，再拉开 / 靠拢 | 放大 / 缩小；松开后加载街区 |
| 单手张掌，朝目标屏幕连续划动约 0.2–0.6 秒 | 将地图化作粒子，向左 / 右 / 上 / 下相应方向传送 |
| 放下手或握拳 | 停止当前动作 |

动作先稳定约 0.12 秒才生效，带捏合滞回、平滑、移动阈值、跳变限制及分屏冷却，降低误触。划屏至少使用三个连续采样点判断方向、距离、速度和直线程度；单帧跳变、小幅抖动不会分屏。允许约 0.22 秒的短暂跟踪丢失。只在地图有效、设置/输入/退出层关闭时接收地图手势。

## 多屏与独立窗口

底部可选择目标屏幕，或保留“自动选择另一屏”。“地图移到另一屏”提供与手势相同的入口，不需要摄像头才能分屏。

程序读取 Windows 实际扩展显示器工作区，在目标屏幕打开普通地图窗口。只有一块屏幕时仍可打开独立窗口，界面会明确说明；镜像显示模式不会变成独立工作区。

## 粒子传送与副屏独立性

目标窗口先隐藏预热并等待几何和首帧就绪。随后主屏地图约用 1.45 秒散成粒子并飞向屏幕边缘；主屏完成离屏后才显示目标窗口，副屏从相反边缘接收粒子，约用 2 秒汇聚重组成三维地图及文字界面。界面字形也采样成粒子，汇聚末段再渐显可操作控件。主屏在传送末段恢复能量体。道路、建筑骨架和路线都采样为粒子，使用有预算的 GPU 顶点变形，不录制/播放一段假地图视频。

两个网页窗口分别绘制离屏和入屏效果，按实际显示器工作区方向协调；不创建覆盖其他 Windows 应用的全桌面透明层。窗口不全屏。

传送后副屏保留当时的路线，独立切换交通方式、加载沿途街区、拖动、旋转、缩放和调整楼高。主屏继续对话、接受新任务、打开新地图或结束主屏导航，都不会覆盖或关闭副屏内容。副屏已有地图时，再次传送不会静默替换，先在副屏关闭当前地图再传送。

手势目标下拉框提供“操作主屏地图 / 操作副屏地图”。传送后默认指向副屏；这是明确的遥控输入，主屏普通对话与新导航不会变成副屏操作。摄像头只开在主窗口，图像不转发，副屏只接收白名单手势动作。

副屏按 **Esc**、点击“关闭此地图”或 Windows 关闭按钮，即可自行关闭；主屏继续运行，也不会被塞回旧地图。主屏提供显式“关闭副屏地图”入口，但不需要主屏发出信号才能退出。

副屏不含麦克风、文字输入或设置；F8/F9/Enter 不触发录音、摄像头或对话。后端为副屏发放独立受限令牌，禁止录音、对话、设置、停止音频和退出整个程序。允许副屏独立读取城市上下文。

独立性指地图内容、交互和退出独立；两个窗口仍复用同一个 Python 本机数据服务。退出整个 JARVIS 会关闭相关窗口。副屏不需要主屏网页持续轮询才保持内容。

## 安装与存储

Python 仍使用标准库；手势识别使用 **MediaPipe Tasks Vision 0.10.21 / Hand Landmarker** 预训练模型，在浏览器后台 Worker 优先以 GPU 执行；不支持 GPU 时回退 CPU。冷启动内核在加载阶段预热，避免首帧误判超时。画面保持实际宽高比例，结合世界坐标关节角度判断手形。采用单个在途画面，GPU 最多约 13 次/秒、CPU 最多约 9 次/秒的采样，不在渲染线程执行推理；实际识别频率取决于电脑。

安装可选手势运行库：

```powershell
.\scripts\install_hand.cmd
```

或在已有 .venv 下执行：

```powershell
.\.venv\Scripts\python.exe -B scripts\install_hand.py
```

下载官方 npm 包和 Google 模型文件，按 config/hand-runtime.json 中固定版本及 SHA-256 校验。约 26 MB 解压资源存于 cache/hand-runtime，下载压缩包也留在根目录缓存。运行时只从本机加载，不依赖 CDN；失败时显示安装或校验提示。安装后重启 JARVIS。

摄像头图像在浏览器内处理，不上传聊天 API、不保存录像、不写入数据库。只同步地图数据和受限数值操作。关闭手势、主窗口隐藏、设备断开或退出时停止轨道和识别线程。浏览器权限及系统摄像头驱动仍由 Windows/Edge 管理。

## 验证

```powershell
$env:PYTHONPATH = 'F:\Javis_os\src'
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
npm test
.\.venv\Scripts\python.exe -B scripts\check_hand.py
```

可选的真实摄像头和原生独立窗口检查：

```powershell
.\.venv\Scripts\python.exe -B scripts\check_hand.py --camera --native-window
```

该检查实际开启摄像头，但不录音、不保存图像；可能触发设备权限。地图路线使用明确的合成测试数据，不发送真实导航凭证。真实 WASM/模型推理、合成关键点动作和真人手势准确率是不同验证项目。真人准确率需要在现场以实际光照、距离和姿势验收；仅单屏电脑不能证明跨物理副屏放置已完成验收。报告仅保存到本机 logs/hand_workspace_check.json。

## 架构

- domain/map_workspace.py：传送时冻结路线种子、窗口代次、方向和有界摄像头动作队列。主屏后续发布与种子隔离。
- presentation/desktop/map_windows.py：读取实际屏幕及主窗口位置，按方向选择目标工作区，创建/放置/关闭普通窗口。
- infrastructure/vision/runtime.py：校验并提供固定本机运行库。
- web/assets/features/hand：关键点动作解释、摄像头生命周期和识别 Worker。
- web/assets/features/map/workspace.js：主屏传送流程与显式手势目标，不替副屏保存其日常视野。
- web/assets/map.js：副屏自己的 NavigationController、城市数据请求、操作和退出。
- web/assets/rendering/transfer.js、assembly.js、city.js、energy.js：传送时序、道路粒子预算、离屏/入屏变形、主屏能量体恢复。

传送种子仅在新传送时读取；副屏自己获取城市数据，不重复做高德出行规划。摄像头动作队列最多 32 项，单帧识别最多一个在途，粒子与 GPU 缓冲保持预算。传送时不更改两侧状态栏布局。

识别接口依据：[Google Hand Landmarker Web 文档](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)。关键点转地图动作是透明规则，没有重新训练手势模型。

地图几何由独立 city_worker.js 后台计算；只保留一个在途任务和最后一个待处理视野。旧结果不能覆盖新街区；等待期间保留旧画面，新几何准备好后原子替换并重置平移，复用 GPU 缓冲。
