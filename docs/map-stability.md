# 地图卡顿与退出稳定性修订

本修订只在 feature/map-update。主分支运行代码不变。

## 已修正路径

- 地图数据同时最多一个请求执行，只保留最新待加载视野，防止连续拖动/缩放把本机连接和后台下载堆满。
- 视野替换复用已分配的顶点缓冲；容量增加时先释放旧缓冲。步道距离缓冲也复用，文字贴图与材质按生命周期释放。
- 粒子城市常规预算改为 36000，F6 节能模式为 16000；保留建筑骨架与完整路线。
- 稳定地图模式关闭无用泛光计算，后处理从六次降为一次；能量体与过渡仍保留原效果。
- 活窗口不再因为超过八秒未轮询就被后台关闭；用户真正关闭窗口或明确退出才结束。
- 退出时先停止后台音频工作并等待，再释放音频资源。客户端已断开时不重复向同一连接写错误响应。

这些是已定位的应用层负载和误退出问题；系统异常模块未获进一步读取，不能据此宣称所有显卡或音频驱动层异常均已排除。

## 可复现压力检查

在安装于 F:\Javis_os 的功能分支运行：

```powershell
.\.venv\Scripts\python.exe -B scripts\stress_map.py
```

检查使用独立浏览器、临时数据库和合成 SDK，不发送真实地图凭证、不录音、不播放语音。生成 500 栋明确标记为测试数据的建筑，连续替换视野 80 次，测量实际 WebGL createBuffer/deleteBuffer 及几何、纹理、程序数量。

本机本轮结果：约 24 FPS，80 次替换新增缓冲为 0，几何 21、纹理 5、着色程序 10，前后数量一致。结果不等于所有设备或数小时使用均已验证；报告保存在本机 logs/map_stability_pressure.json。

116 项 Python 单元测试、Node 请求合并与几何/手势检查、实际 Chromium 回归通过。另行使用真实高德路线复测全程与终点拖拽，私人路径和截图不公开。

## 日常操作

地图默认左键移动、右键或 Shift 拖动环绕。滚轮缩放，“查看全程”恢复起终点，F6 可切换节能特效。遇到问题可提供不含地址/Key 的阶段、提交号和错误摘要；不要直接上传 .env、录音或完整私人日志。
