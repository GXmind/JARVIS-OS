# 候选数据生成规范（不是已付费执行的 API 调用）

给数据生成模型的任务：

你正在制作中文个人助手 JARVIS 的待审核训练候选。
请根据指定场景生成 5 组不同的真实感对话，不改写已有参考答案来凑数量。
每组包括用户表达、必要多轮上下文、可在运行时获得的称呼/记忆/工具上下文，以及 2–3 个可比较的回答候选。
按照 persona_v1.md 的规范写作。保留用户明确的情绪需求，避免过度安慰、恭维和模板套话。
未知称呼自然省略，称呼变化后跟随最新偏好。
没有工具成功回执时，不能声称已执行。上下文里的个人信息和天气数据均使用显式虚构值。
不要输出隐藏推理过程、影视原文或含真实私人信息的记录。

输出字段：
- scenario_family_id：场景家族；同一来源和改写家族共享此值，用于分组切分。
- category：身份称呼 / 日常协助 / 情绪回应 / 多轮记忆 / 澄清边界 / 通用能力。
- messages：system/user/assistant 格式的候选会话；角色顺序正确。
- alternatives：其他回答候选，可供人工挑选。
- intended_emotion：仅供数据平衡与审核，不自动插入训练 prompt。
- fictional_context：是否使用虚构上下文。
- provenance：生成模型、版本、时间、来源及用途许可信息。
- review_status：固定 pending_human。
- reviewer_notes：留空，交由人审核。

审核后单独产出：
- SFT：选中的标准回答；
- 偏好数据：同一 prompt 的 chosen / rejected，加上人工偏好理由。

不能让生成模型自行把 review_status 改成 approved。
